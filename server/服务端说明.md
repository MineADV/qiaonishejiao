# 悄匿社交 · 服务端使用说明

> 本说明对应 **2026-09-25 21:08** 打包的服务端（`悄匿社交-服务端.exe`）。
> 这是一个 UDP 局域网 / 公网聊天服务的服务端：负责账号、好友、群组、消息转发、
> 文件与头像分发、中国象棋裁判，以及每个用户的 IP 属地判定。

---

## 1. 怎么跑起来

**方式一：直接双击（推荐给演示）**

```
悄匿社交-服务端.exe
```

第一次运行会在**同目录**生成 `server_config.json`，然后开始监听 UDP **26000** 端口。
控制台会打印：

```
◆ 本机对外地址：203.0.113.9
[19:20:31] ✓ 服务端已启动   端口 26000 · 房间「公共大厅」
```

**方式二：用源码跑（改代码 / 调试时用）**

```
set PYTHONPATH=D:\dsh;D:\dsh\site-packages
py chat_server.py                 # 用 server_config.json 里的端口
py chat_server.py --port 27000    # 临时换端口
py chat_server.py --room 演示大厅  # 临时换大厅名字
py chat_server.py --host 127.0.0.1  # 只监听本机（本机自测最安全）
```

| 参数 | 作用 | 默认 |
| --- | --- | --- |
| `--host` | 监听地址 | `0.0.0.0`（所有网卡） |
| `--port` | UDP 端口（覆盖配置文件） | 配置文件里的 `port` |
| `--room` | 公共大厅名称 | 配置文件里的 `room` |

> 一个端口只能被一个服务端占用。想在同一台机器上开第二个，必须换端口，
> 否则第二个会因为端口被占用而启动失败。

## 2. 服务端目录里有什么

| 文件 / 目录 | 内容 | 会不会自动生成 |
| --- | --- | --- |
| `server_config.json` | 全部可调参数（见第 3 节） | 首次运行生成 |
| `social_data.json` | 账号（盐 + PBKDF2 口令散列）、好友关系、群组、拉黑、入群/拉人邀请、群公告、群文件索引、头像版本号 | 首次有账号时生成 |
| `history/` | 各会话的离线历史（按会话分文件，重启后仍在） | 有历史时生成 |
| `avatars/` | 用户上传的头像（256×256 PNG，按昵称 + 版本号命名） | 有人设头像时生成 |
| `client_error.log` | **服务端**写在这里的只可能是极少数内部异常（正常情况下没有这个文件） | 出错时 |

> 换服务器时，把这几个文件一起拷走 = 账号、好友、群、历史、头像全部保留。

## 3. `server_config.json` 每一项

```json
{
  "port": 26000,
  "room": "公共大厅",
  "geo_lookup": true,
  "public_ip": "",
  "super_admins": [],
  "geo_api": "",
  "geo_overrides": {}
}
```

| 字段 | 含义 | 怎么改 |
| --- | --- | --- |
| `port` | 监听端口（UDP）。客户端要填一样的数字 | 想换端口就改这里，或启动时加 `--port` |
| `room` | 公共大厅显示的名字（所有客户端都会看到） | 直接改文字 |
| `geo_lookup` | 是否联网判定「每个用户来自哪个省市」 | 内网 / 不想联网就改 `false`，属地会显示「本机」或「公网」 |
| `public_ip` | 手写服务端自己的公网 IP（用于客户端里显示的「服务器 属地」） | 留空 = 自动探测；探测不准时手动填 |
| `super_admins` | 超级管理员昵称列表（小写）。这些人登录后右上角会出现「🛡 控制台」 | 例：`["zhangyibo"]` |
| `geo_api` | 自建/第三方 IP 属地查询接口（URL 里用 `{ip}` 占位） | 留空 = 用内置的多个公开数据源 |
| `geo_overrides` | 手动指定某个 IP 的属地（优先于任何查询） | 一般由控制台 `geoset` 写，不用手改 |

> 文件用 **UTF-8（带 BOM 也能读）**。用记事本另存为 UTF-8 即可。

## 4. 控制台命令（在服务端窗口里直接敲）

| 命令 | 作用 |
| --- | --- |

| `users` / `list` | 当前在线的人 + 在线账号数/群数统计 |
| `stats` / `stat` / `状态` | 账号数、群数、在线人数、头像数、离线留言数；逐群列出成员/管理员/公告/群文件/待审批 |

| `admin list` | 看超级管理员名单（配置文件里写死的 + 控制台加的都列出） |
| `admin add <昵称>` / `admin del <昵称>` | 运行时增删超级管理员（会写回配置文件） |
| `ban <昵称> [分钟\|0] [理由]` | 封号；`0` 或省略分钟数 = 永久。理由会显示在被封的人登录时 |
| `unban <昵称>` | 解封 |

| `files` | 文件目录、群文件、头像、历史目录的位置与数量 |
| `quit` / `exit` | 关服（会先给所有在线客户端发「服务器已关闭」） |

## 5. 网络与部署

**局域网**：拷到任何一台机器双击即可，客户端填这台机器的内网 IP（例如 `192.168.1.20`）。
Windows 防火墙第一次会弹窗，选**允许**（专用网络即可）。没弹窗就去「高级安全 Windows 防火墙 →
入站规则 → 新建规则 → 端口 → UDP 26000 → 允许」。

**公网**：需要两件事同时做对，缺一个客户端就连不上：

1. 云服务器**安全组**放行 UDP 26000（注意是 **UDP**，不是 TCP）；
2. 路由器端口映射（家里宽带）/ 直接给公网 IP（云服务器）。

**怎么自查**：客户端登录时如果一直转圈，就是包没到服务端。依次检查
安全组 → 防火墙 → 端口是否被别的程序占用 → 服务端窗口有没有打印启动成功。
服务端控制台用 `geo self` 能看到自己对外解析出的地址。

**建议的规模**：一台普通家用/云主机（1 核 1G）跑几十人在线没问题。
开销主要在加密（每条消息 AES-GCM）和群发（一个群 N 人 = N 份报文），

## 6. 账号与安全

- **昵称**：2–16 个字符，支持中文/字母/数字/下划线/短横线，**全服唯一**（不区分大小写）。
- **密码**：至少 4 位。服务端只保存 `PBKDF2-HMAC-SHA256(密码, 每个账号独立的随机盐)`，
  **迭代 20 万次**，不保存明文。
- **登录**：客户端发昵称 → 服务端回盐 + 一次性随机数 → 客户端用
  `HMAC(密钥, 随机数)` 应答 → 服务端比对。**密钥和密码都不上网**。
- **通信加密**：认证成功后，除 `HELLO`/`DENY` 外**所有报文都用 AES-256-GCM 加密**
  （密钥由盐派生 + 会话随机数协商），报文里带 16 字节随机会话号，源地址变了也认得出是自己人。
- **同一账号重复登录**：新连接生效，旧连接会被提示并断开。
- **已知限制（务必知情）**：注册请求里的密码仍然是**明文**发一次（首个报文还未协商密钥）。
  服务端只用于本地/内网演示。要做到滴水不漏，需要把注册改成「先协商密钥再传口令」的两段式。

## 7. 传输层（为什么 UDP 也能可靠）

每条业务消息走自定义可靠信道，摘要：

| 机制 | 参数 |
| --- | --- |
| 报文头 | 固定 **34 字节**：`>4sBBBBII16sH` = 魔数 `DCHT`、版本、类型、标志、保留、序号、确认号、会话号(16)、负载长度 |
| 类型 | `K_DATA` 数据、`K_ACK` 确认、`K_PING` 心跳、`K_PONG` 心跳应答 |
| 标志位 | `F_ENC` 已加密、`F_RESET` 重建会话 |
| 发送窗口 | 128 个包；每 tick（5ms）最多发 24 个，空闲时降到 20 次/秒省 CPU |
| 确认 | 累积确认 + **重复确认 3 次即快速重传** |
| 超时重传 | `RTO = srtt + 4×rttvar`，范围 0.2–4 秒，每包独立指数退避（最多再退 2 次） |
| 尾包 | 在途包很少时按 `max(0.4s, 2×srtt)` 主动补发，避免最后一个包丢了没人触发重传 |
| 永不放弃 | 单个包**不会**因为重传次数多而被丢弃 |
| 乱序 | 接收端缓存 320 个包，按序号重组 |
| 不分片 | 单个业务报文控制在 MTU 内，文件按 1000 字节分块流式发送 |

**保活与判死（两档）**：

| 情况 | 行为 |
| --- | --- |
| 连续 **8 秒** 收不到任何报文 | 只在客户端顶部提示「网络不稳，正在自动重试」，**不断开**、不锁输入框 |
| 连续 **45 秒** 收不到 | 判离线；客户端自动重连（2/4/8/15/25 秒，共 5 次） |
| 窗口 **120 秒** 毫无确认进展 | 同样判离线（真断了不会永远挂着） |

服务端用同一套阈值，不会因为客户端抖一下就把会话踢掉；客户端进程自己卡顿（GC、杀软扫描）
超过 1 秒时会按卡顿时长顺延判死计时，不会误报。跨洋高延迟（600ms RTT）实测可稳定传完文件。

## 8. 数据、限额与清理

| 项目 | 取值 | 说明 |
| --- | --- | --- |
| 公共大厅历史 | 保留最近 **200 条** | 客户端重开窗口可拉取 |
| 群历史 | 入群时补发最近 **30 条** | 之后正常收发 |
| 单条消息 | 最长 **2000 字** | 超长客户端会提示 |
| 群成员上限 | **60 人** | 建群/拉人时校验 |
| 群号 | 6 位数字 | 建群时自动分配，可一键复制 |
| 上传文件 | 服务端落在 `%TEMP%\qiaoni_server` | 服务端重启后旧 fid 失效，客户端会按需重新上传 |
| 头像 | 服务端 `avatars/` 目录 | 客户端按版本号按需拉取，缓存在本地 |
| 离线留言 | 保留 **30 天** | 过期自动清理 |
| 消息撤回 | 自己 **2 分钟内**；群主/管理员撤群成员不限时间 | 撤回由服务端判定权限与时限 |

## 9. IP 属地是怎么判的

- **只看 UDP 报文的来源地址**，完全不采信客户端上报的任何信息，所以客户端改不了。
- 多个公开数据源**投票 + 择优**，只显示中文地名（如「福建 厦门」）。投票规则：
  1. **同一个上游库的多个域名只算一票**（`ipwho.is` 与 `ipwhois.app` 是同一份数据），
     否则一家库能凑出「两票多数派」；
  2. **熟悉的库按准确度加权**：`pconline` / `ip.sb` / `ipinfo` 记 3 分，`vore` / `useragentinfo` 2 分，
     `ip-api` / `ipapi.co` / `ipwho` 1 分；
  3. 先比「几家库指向同一个省」，再比加权分，最后才比数据源顺序；省内再比城市；
     两家以上库一致才叫共识，没有共识时取「更细 + 更可信」的那家。
  4. 只要有国内库回过话，就不再仅凭境外库的一致结论提前收工 —— 移动/家宽出口 IP
     被境外库登记成「北京」正是老毛病（实测某个移动出口 IP：境外库报北京/广东，
     国内库报福建 厦门）。
- 成功结果缓存 24 小时，失败缓存 5 分钟，避免刷接口；**换了新版本要重启服务端**，
  否则内存里还是旧结论。
- 想排查某个 IP：控制台 `geo 1.2.3.4`（会逐个数据源列出结果和票数）；想手动指定：
  `geoset 1.2.3.4 福建 厦门`，再 `geo save`。
- 内网/离线：把 `geo_lookup` 设为 `false`，属地统一显示「本机」或「公网」。

## 10. 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 客户端一直连不上 | 安全组/防火墙没放 **UDP** 26000；或端口被占用；或客户端填错 IP/端口 |
| 私聊里对方收不到图片/文件 | 旧版服务端只把文件投递给大厅/群，私聊会漏投（本版已修）；换新服务端后自动正常 |
| 大厅里冒出「头像已更新」之类的怪消息 | 旧版服务端的系统提示默认记成大厅消息（本版已修）；新服务端 + 新客户端一起换即可 |
| 控制台报端口被占用 | 已经有一个服务端在跑（或别的程序占了 26000），换端口或先关掉旧的 |
| 属地显示「属地未知」 | 联网查询失败：控制台 `geo self` 看原因；或配 `geo_api`；或直接 `geoset` 手动指定 |
| 「本机对外地址」是 127.0.0.1 | 机器没有公网出口（内网环境正常现象），不影响局域网使用 |
| 服务端重启后老客户端卡住 | 客户端心跳（3 秒）会收到「会话失效」标记并自动重连，最多等几秒 |
| 想清空所有数据重来 | 关掉服务端，删掉 `social_data.json`、`history/`、`avatars/`，再启动 |
| 想换端口又要保留数据 | 只改 `server_config.json` 的 `port`，其他文件别动 |

## 11. 这个版本包含 / 不包含

- ✅ 账号登录注册（PBKDF2 + challenge-HMAC + AES-GCM）、好友、黑名单、群组（管理/禁言/公告/群文件/拉人审批）、离线留言、文件与头像、撤回、中国象棋、IP 属地、超级管理员控制台
- ✅ 传输层健壮性：滑动窗口、累积确认、快速重传、尾包补发、两档判死、自动重连、地址漂移跟随
- ❌ **不含**游戏中心（五子棋 / 成语接龙 / 战绩排行榜）—— 那部分已在回滚中移除
- ❌ 不含端到端加密：服务端能看到消息明文（局域网/演示用途）
